# 재정렬(리랭커) 비교 실험

같은 검색 후보를 두고 재정렬 방식만 바꿔 정확도와 속도를 비교했어요.

| 구성 | 재정렬 | 모델 |
| --- | --- | --- |
| R0 | 없음 (Dense + BM25 → RRF) | BAAI/bge-m3 |
| R1 | ColBERT | BAAI/bge-m3 (토큰 벡터) |
| R2 | 크로스 인코더 | BAAI/bge-reranker-v2-m3 |

## 결과 (최종 198문항: test 151 + 불확실 29 + 법령 18, 후보 50개, Colab L4)

| 구성 | Hit@1 | Hit@3 | Hit@5 | Hit@8 | MRR | 재정렬 시간(문항당) |
| --- | --- | --- | --- | --- | --- | --- |
| R0 재정렬 없음 | 0.354 | 0.646 | 0.712 | 0.778 | 0.505 | 0 |
| R1 ColBERT | 0.374 | 0.621 | 0.707 | 0.788 | 0.509 | 186ms |
| R2 크로스 인코더 | 0.404 | 0.682 | 0.793 | 0.828 | 0.553 | 572ms |

| 묶음 | 문항 | R0 Hit@8 | R2 Hit@8 | R0 Hit@1 | R2 Hit@1 |
| --- | --- | --- | --- | --- | --- |
| test | 151 | 0.788 | 0.828 | 0.424 | 0.437 |
| 법령 | 18 | 0.611 | 0.833 | 0.111 | 0.444 |
| 불확실 | 29 | 0.828 | 0.828 | 0.138 | 0.207 |

- ColBERT는 재정렬 없음과 차이가 없어 제외했어요.
- 크로스 인코더는 검색 순위를 개선했어요. 법령이 정답인 문항에서 효과가 커요.
- 답변 정답률까지 오르는지는 아직 확인하지 않았어요. 그래서 패키지 기본값은 재정렬 없음이에요.
- dev 72문항(후보 20개)에서는 Hit@8이 R0 0.875, R2 0.889였어요.
- 후보 50개 안에 정답이 없는 문항이 7.6%예요. 검색 단계의 개선 여지가 재정렬보다 커요.

## 방법

- 채점: 조항 단위. 찾은 조각이 정답 조각과 같거나 같은 문서·같은 조항이면 맞음
- 검색 구성: A1 (Dense + BM25, 카테고리 필터 없음)
- 문항 묶음: LLM 평가와 같은 나눔(seed 42). 설정은 dev로 정하고 test는 한 번만 실행
- 시간: 구성마다 저장해 둔 계산 결과를 비우고 측정. 모델을 처음 불러오는 시간은 제외

## 파일

| 파일 | 내용 |
| --- | --- |
| `rerank_eval.ipynb` | 실험 노트북 (Colab) |
| `results_v1/` | 결과 표: 구성별 요약, 문항별 결과, 묶음별, 순위가 바뀐 문항, 못 찾은 문항 |
| `run_log_v1.txt` | 실행 기록 |
| `splits.json` | 문항 묶음 (문항 ID → dev / test / 불확실 / 법령근거없음) |
| `make_pack.py` | 노트북이 읽는 묶음 파일(`rerank_exp_pack.zip`)을 다시 만드는 스크립트 |

## 다시 실행하기

```bash
python experiments/rerank/make_pack.py --db ../DB --golden ../goldenset
```

만들어진 `rerank_exp_pack.zip`과 `rerank_eval.ipynb`를 구글 드라이브의 한 폴더에 올리고, Colab에서 GPU 런타임으로 모두 실행해요.
묶음 파일은 저장소에 올리지 않아요 (코드와 데이터가 각 저장소에 이미 있어요).
